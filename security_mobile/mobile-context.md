# سياق المشروع — الموبايل (`security_mobile`)

آخر تحديث: 2026-11-04  
السياق العام: [`../system-context.md`](../system-context.md) · التقدّم: [`mobile-progress.md`](./mobile-progress.md)

## الهوية

| الحقل | القيمة |
|--------|--------|
| المسؤولية | تطبيق مالك Flutter (Android/iOS): جلسة، أجهزة، أوامر، سجلات، FCM عميل، Wi-Fi محلي |
| التقنية | Flutter · RTL عربي · flavors dev/staging/prod |
| مسار العمل | `security_mobile/` — حالياً تخطيط فقط؛ لا كود تطبيق بعد |
| لا يملك | لوحة أدمن · MQTT مباشر · إنذار محلي · عامل FCM على الخادم |

## مبادئ ملزمة

- التطبيق لا يتصل بـ MQTT ولا يستبدل الإنذار المحلي.
- نجاح HTTP لا يقلب المؤشرات المؤكدة؛ الحالة من الخادم بعد تأكيد الجهاز.
- لا أسرار خادم أو مفاتيح خاصة أو اعتمادات إنتاج داخل Git. إعدادات عميل Firebase العامة (مثل App ID/API Key) ليست أسرار خادم بذاتها، لكنها تُراجع وتُقيّد بحسب البيئة ولا تُخلط مع مفاتيح FCM Service Account أو APNs الخاصة.
- إعداد/تغيير Wi-Fi محلي بين التطبيق والجهاز فقط — لا تخزين كلمة المرور في الخادم.
- عقد المصادقة المنفّذ في Backend T-02: Access JWT قصير العمر في الذاكرة، وRefresh دوّار في التخزين الآمن للنظام بالموبايل؛ يُرسل في جسم طلب HTTPS. يُمنع تجديدان متزامنان للرمز نفسه عبر single-flight.
- الربط الأولي PENDING يعرض معلومات محدودة؛ نقل الملكية ينشئ ملكية ACTIVE خادمياً، ويجوز للمالك الجديد المتصل جهازه **تقديم طلب أمر** وفق قيود الأوامر؛ يحتجز الخادم **نشر الأمر وتنفيذه** حتى تأكيد مزامنة إصدار الملكية على الجهاز.
- تنفيذ Backend T-02 لا يعني اعتماد كل عقد HTTP المشترك أو اجتياز G1/G2، ولا يعني وجود كود Flutter.
